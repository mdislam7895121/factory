## How Each Serial Contributes

### Serial 27 — Production Monitoring
**What it provides:** Automated smoke checks every N minutes. Slack alerts if the site goes down.  
**How it connects:** Founder daily routine starts with checking the status page generated by SYNTH-01.  
**Integration point:** `scripts/watch-production.ps1` → ALERT_SLACK_WEBHOOK_URL (Railway env var)

---

### Serial 29 — Customer Feedback Loop
**What it provides:** Feedback widget → in-memory ticket store → pain ranking → roadmap suggestions.  
**How it connects:** Every user interaction with the feedback widget creates a ticket. Tickets feed the pain ranking. Pain ranking informs which roadmap items to schedule next.  
**Integration point:**
- Frontend: `FeedbackWidget` on every page → `POST /v1/feedback`
- Admin: `/admin/support` → pain ranking → roadmap view
- CS CRM link: map `submitterHash` to `emailHash` in CS CRM by storing both at invite time (future sprint)

**Roadmap output from pain ranking:**
```typescript
// api/src/feedback/feedback.service.ts
toRoadmapSuggestions(pains) → { urgency: IMMEDIATE|NEXT_SPRINT|BACKLOG, affectedModule, ... }
```

This directly informs what goes in SERIAL 34, 35, etc.

---

### Serial 30 — Onboarding + Activation Engine
**What it provides:** 4-step onboarding flow, activation state tracking, stuck detection, next-best-action.  
**How it connects:** Every user gets a `userId` on the onboarding page. Their activation journey is tracked via events.  
**Integration point:**
- Frontend: `/onboarding` page → `POST /v1/onboarding/:userId/event`
- CS CRM link: when a user joins as a beta lead, map their `userId` to their `leadId` (future sprint — call `patchLeadActivity` on the CS service when onboarding events fire)
- Stuck detection: `detectStuck()` → trigger `ACTIVATION_NUDGE` task in CS CRM

**How to wire onboarding → CS CRM (integration path):**
```typescript
// Future: in OnboardingService.recordEvent()
// after saving to in-memory store:
if (csService) {
  csService.patchLeadActivity(leadId, {
    onboardingState: profile.state,
    onboardingStepCount: profile.completedSteps.length,
    demoCompleted: profile.completedSteps.includes('DEMO_STARTED'),
    previewRevealed: profile.completedSteps.includes('PREVIEW_REVEALED'),
    workspaceOpened: profile.completedSteps.includes('WORKSPACE_CREATED'),
  });
}
```

---

### Serial 31 — Customer Success CRM
**What it provides:** Cohort management, lead tracking, health score (8 dimensions), follow-up tasks, notes, activation summary.  
**How it connects:** The CRM is the single source of truth for the founder's view of each beta user.  
**Integration point:**
- Health score inputs: `onboardingStepCount`, `demoCompleted`, `previewRevealed`, `feedbackCount`, `supportTicketCount`, `billingIntent`
- These are updated via `patchLeadActivity()` as signals come in from Serial 29 and Serial 30
- Follow-up tasks auto-suggested by health score: `recommendedAction` string → convert to task type

**How feedback counts flow into CS health (integration path):**
```typescript
// Future: in FeedbackService.create()
// after creating a ticket:
if (csService) {
  const lead = csService.findByEmailHash(ticket.submitterHash);
  if (lead) {
    csService.patchLeadActivity(lead.id, {
      feedbackCount: lead.feedbackCount + 1,
      supportTicketCount: lead.supportTicketCount + (ticket.category === 'BUG' ? 1 : 0),
    });
  }
}
```

### Serial 32 — Go/No-Go
**What it provides:** Live deployment verdict. Infrastructure readiness check.  
**How it connects:** Nothing ships to users until the go/no-go tracker says `GO_FIRST_5_BETA`.  
**Integration point:** `docs/beta/go-no-go-tracker.md` — updated manually by founder as each check passes.

## How Customer Learning Flows into the Roadmap

```
User experience → feedback widget → /admin/support/pains → pain ranking
                                                               │
                                                    toRoadmapSuggestions()
                                                               │
                                          IMMEDIATE  │  NEXT_SPRINT  │  BACKLOG
                                                     │
                                               Founder review
                                               (daily routine: item 6)
                                                     │
                                        Add to next SERIAL spec
                                        (SERIAL 34, 35, etc.)
```

**Decision rule:**
- 1 user says it → note it
- 3 users say the same thing → add to next sprint
- 5 users say the same thing → it's a blocker, move it to IMMEDIATE
